# AI 用量插件

[English](./README.md) | **简体中文**

用一句话回答"我今天用了多少 AI"，同时把一张分成两栏的用量表推到通话对端的屏幕上：左边
Claude Code，右边 Codex，每一栏都带五小时窗口和一周窗口。

```text
AI USAGE
══════════════════════════════════════
 CLAUDE            │ CODEX
 as of 06:11       │ as of 06:08
 5H 62% used       │ 5H 16% used
 ======----        │ ==--------
 38% left @14:10   │ 84% left @10:53
 7D 17% used       │ 7D 16% used
 ==--------        │ ==--------
 83% left @Sep 7   │ 84% left @Sep 11
```

说一句"给我看看我的 AI 用量"，模型就会调用 `ai.usage`。这个工具会把拿到的每个数字都念出来，
同时发出一个使用 `split` 布局的 `display.card` v1 数据包。

> **`split` 是新增布局。** 本仓库里的
> [zectrix-note4c](../../../../examples/zectrix-note4c) 固件已经能渲染它，但仍然跑着旧固件的
> 设备会把这张卡片当作未知布局拒掉，屏幕上保持原样。想看到画面变化，先重新烧录固件。

## 数字从哪里来

这两个工具都没有提供查询自身限额的接口，所以两份读数都是从它们本来就会写的文件里捡出来的。
全程不出本机，也不读取任何凭证。

| Agent | 数据源 | 说明 |
| ----- | ------ | ---- |
| Claude Code | `~/.claude/plugins/claude-hud/eink-snapshots/*.json` | Claude Code 只把套餐用量百分比通过 **stdin 交给状态栏**，别处都没有。必须有东西把它落到磁盘上；这里读的就是 claude-hud 状态栏包装脚本写下的快照。限额是按账号算的，所以取时间戳最新的那份 |
| Codex | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` | Codex 把 `rate_limits` 嵌在 `token_count` 事件里。读取时按日期目录倒序下钻，从最新的日志尾部往回找，直到找到一条为止 |

两个数据源在对应工具停止运行的那一刻就开始变旧，所以每一栏的第一行写的就是这一栏的数据是
什么时候取的（`as of 06:11`；如果已经不是今天，就写成 `as of Sep 4`）。一边旧不会连累另一边
看起来也不可信。这里用绝对时间而不是相对时间，是因为面板可能一个小时都不刷新一次：
`as of 06:11` 挂在屏幕上依然成立，`2m ago` 不成立。

文件没有回答的窗口显示 `no data` 而不是 `0%`；完全没有数据的 agent 会在本该是数据行的位置
直接说明这一点。栏里放不下的"这份读数有多旧"，由口播补上。

## 配置

默认关闭，因为这些路径只在真正跑过这两个工具的机器上才存在。

```toml
[plugins.config."ai.usage"]
enabled = true

# 以下均可选，这些就是默认值。
claude_snapshot_dir = "~/.claude/plugins/claude-hud/eink-snapshots"
codex_sessions_dir  = "~/.codex/sessions"
stale_after_minutes = 30
codex_scan_files    = 8
```

如果你的状态栏把快照写在别处，把 `claude_snapshot_dir` 指过去即可。读取器期望的 JSON 形状是：

```json
{
  "timestamp": "2026-09-06T11:50:00Z",
  "usage": {
    "fiveHour": 62,
    "sevenDay": 17,
    "fiveHourResetAt": "2026-09-06T14:00:00Z",
    "sevenDayResetAt": "2026-09-08T00:00:00Z"
  }
}
```

没有 `usage` 对象的文件会被跳过，这样一个还没见过限额数据的状态栏不会被当成"用量为零"。

## 这张卡片

用的是 `split` 布局：一个标题，下面是被分隔线隔开的左右两栏短文本。它的形状由三条约束决定：

- **两栏，每栏 17 字符、7 行。** 这是 400 px 宽的面板在 10 px 字宽下，还能隔着房间看清的极限。
  上限定义在 `note4c-logic/src/display_card.rs`，插件这边照抄同一组数字。
- **进度条用 `=`、`-`、`.`，不用方块字符。** note4c 在渲染前会把所有非 ASCII 字符换成 `?`，
  而 `#`、`*` 和方括号会被 display projector 的清洗逻辑当作 markup 拒掉。
- **任何一栏都不靠连续空格对齐。** 卡片解析器会把连续空白压缩成一个空格，用空格补齐到固定列
  的内容传到设备上只剩一个空格。对齐这件事交给中间那条分隔线。

一共只有七行的预算，所以重置时间和"还剩多少"挤在同一行（`38% left @14:10`），而不是单独占一行。
五小时窗口给的是时钟时间，一周窗口给的是日期——对于六天之后才重置的窗口，`@16:00` 什么也说明不了。

栏内的空字符串是占位行：面板为它留一行但不画任何内容。本插件已经没有多余的行去放它，但这个
布局是支持的。

和 `display-projector` 一起启用前有一点需要知道。服务端把工具发出的数据包原样透传，不会补上
轮次编号，所以本插件用墙上时钟秒数给自己的卡片编号，以保证"刚刚问出来"的卡片一定能抢到客户端
那个 latest-wins 的槽位。客户端只保留同一会话里见过的最大序号，因此一旦显示过一张用量卡片，
projector 那些按对话自身的小计数器编号的卡片，在这次会话剩下的时间里就抢不过它了。

## 文件

| 文件 | 作用 |
| ---- | ---- |
| `plugin.yaml` | 清单。工具名、模型看到的描述、`enabled: false` |
| `index.ts` | 接线：initialize 时读配置，execute 时口播 + 发包 |
| `sources.ts` | 读取并归一化两个 agent 的文件 |
| `card.ts` | 进度条、v1 卡片和口播文本 |
| `test.ts` | `npx tsx --test test.ts` |
